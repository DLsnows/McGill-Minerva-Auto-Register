# P6 — API (REST + WebSocket) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** Expose the store + scheduler to a frontend over a local HTTP API: CRUD watch targets, read/update settings (incl. UI-editable email config), session status + login trigger, scheduler start/stop, recent log events, and a WebSocket that streams live events. Serve the built web UI in production.

**Architecture:** Fastify HTTP server + `@fastify/websocket`. Routes are thin adapters over the P5 `Runtime` (store/budget/scheduler/session/notifier). The scheduler's `onEvent` is broadcast to all WS clients. Email SMTP config moves into `Settings` (UI-editable) — `email.ts` reads it from settings instead of env.

**Tech Stack:** TypeScript, Fastify, @fastify/websocket, Vitest (route tests via `fastify.inject`).
